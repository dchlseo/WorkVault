## 갱신 원칙

1. 한국어·영어 사이트의 보고서 메뉴 4종(인사이트·브리프·동향보고서·연구보고서)을 마지막 페이지까지 확인한다.
2. 웹 본문에 제목·저자 정보가 없으면 PDF를 직접 확인한다. 사이트 언어와 PDF 언어를 구분한다. 한·영판, 한국어만 있는 자료, 영어만 있는 자료를 모두 수집 대상으로 삼는다.
3. 보고서와 첨부파일은 별도 테이블로 관리하고, 같은 보고서의 번역판은 동일 보고서 ID에 연결한다.
4. 기존 report_id·attachment_id로 신규 자료를 대조한다. 같은 첨부 ID의 SHA256 변경은 파일 교체로 기록한다. 제목·저자·날짜 변경도 기존 값과 새 값을 보존한다.
5. 웹 등록일과 PDF 발행일을 구분한다. 개인 저자 미표기·확인 불가·월까지만 확인된 발행일은 임의로 채우지 않는다. 문의 담당자나 참고문헌의 이름을 저자로 간주하지 않는다.
6. 최신 DB를 갱신하면서 날짜별 수집 스냅샷을 보존한다. 기존 자료 삭제·공유 권한 변경은 이 작업에 포함하지 않는다.
7. 업로드 후 실제 파일 목록과 크기를 확인한다. 실행일·수집 건수·신규/수정 건수·저장 링크를 당일 저널과 아래 실행 이력에 남긴다.

파일과 데이터는 Drive에 보관하고, WorkVault에는 절차·실행 기록·원자료 링크를 남긴다. 수집 스크립트와 상세 메타데이터 정의는 메타데이터 ZIP의 README·scripts를 참조한다. 새 자료의 PDF 저자·발행일은 확인 후 확정한다.
