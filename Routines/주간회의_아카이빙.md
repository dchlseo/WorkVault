# 주간회의 아카이빙 (Weekly meeting archive)

작성: 2026-11-10 KST. 주간회의가 끝난 뒤 회의 내용을 WorkVault에 남기는 정기 업무다. 다른 AI도 이 노트만 읽고 같은 작업을 할 수 있게 쓴다. 몇 차례 반복한 뒤 skill로 만든다.

- 실행 명령 예: "이번 주 주간회의 아카이빙해줘", "11/3 주간회의 소급 아카이빙해줘"
- 회사 GPT용 지침: [주간회의 아카이빙 — 회사 GPT 작업 지침서](주간회의_아카이빙_GPT지침.md). GPT는 Slack·회사 메일·캘린더도 확인하고 vault 노트를 Markdown으로 출력한다. GPT 출력을 vault에 넣을 때는 같은 날짜 노트에 `## 회의 외 확인 사항` 절로 합치고 `## 변경 기록`에 남긴다.
- 별도 운영: 사용자는 회사 ChatGPT 프로젝트로 Google Sheets 인덱스(`[개인] 주간회의 AI 인덱스`)에도 아카이빙한다. 두 작업은 서로 독립이다. 이 vault 작업은 시트를 읽거나 쓰지 않는다.

## 자료 (읽기 전용)
| 구분 | 파일 | 단위 |
|---|---|---|
| A. 본인 발표자료 (1순위) | [2026Weekly_서대철_주간업무보고](https://docs.google.com/presentation/d/13gmIZ6Ml44bZ1Yx24o5xqQrB21QgwNTAD0cqUZZ1Zec/edit) | 회의 1회 = 슬라이드 1장. 최신이 맨 앞. 제목 `(M.D)` |
| B. 회의 메모 (2순위) | [2026 weekly](https://docs.google.com/document/d/1K49KttjnkKPEHTPgXleQZqQUTgRufuQmF1q4-ssVTcM/edit) | 날짜별 탭(`YYYYMMDD`). 사용자가 회의 중 쓴 자유 메모 |

- 다른 연구원의 발표자료는 찾거나 읽지 않는다. 동료 정보는 B 메모에 적힌 것만 쓴다.
- 기술 메모: Docs 커넥터 `read_doc`은 모든 탭을 한 번에 돌려준다(약 1.5MB JSON). 결과 파일에서 해당 탭 제목만 골라 텍스트를 뽑는다. 탭 이름이 날짜 형식에 맞지 않으면(예: `202607829`) 날짜를 추정하고 `[추정]`으로 표시한다.

## 산출물
- 회의 노트: `Meetings/주간회의/YYYY-MM-DD.md` (회의 1건 = 노트 1개)
- 실행 기록: [Meetings/주간회의/README](../Meetings/주간회의/README.md) 표에 한 줄 추가
- 사람: [조직도](../People/야놀자리서치_조직도.md)와 `People/<이름>.md`. 회의 노트에서 `[[이름]]`으로 연결하면 백링크가 인물별 이력이 된다.
- 주제: 기존 프로젝트 노트(예: [KAC](../Projects/KAC.md))에 링크한다. 아직 노트가 없는 주제는 태그 `#주제/<이름>`로 시작한다.
- 그날 [Journal](../Journal/)에 짧은 실행 기록을 남긴다.

## 절차
1. 대상 회의일을 정한다. 기본은 한국시간 이번 주의 회의다.
2. A 슬라이드와 B 메모 탭을 각각 찾는다. 하나만 있으면 있는 것만 처리하고 빠진 자료를 frontmatter와 README 표에 적는다.
3. 같은 날짜 노트가 있으면 덮어쓰지 않는다. 빠진 자료만 추가하고, 추가한 날짜를 노트 끝 `## 변경 기록`에 남긴다.
4. 직전 회의 슬라이드(그리고 직전 회의 노트가 있으면 그 노트)와 비교해 내 업무가 어떻게 바뀌었는지 쓴다.
5. 템플릿에 맞춰 노트를 쓴다(아래).
6. README 실행 기록에 한 줄을 추가한다. 메모에 새 인물이 나오면 조직도의 "기타 인물"에 추가한다.
7. 검증: 메모의 연구원 섹션이 모두 반영됐는지, 슬라이드의 모든 항목이 반영됐는지, 링크가 맞는지 확인한다.

## 노트 템플릿
```
---
meeting_date: YYYY-MM-DD
type: 주간회의
sources:
  slides: 완료 | 없음 (슬라이드 제목)
  memo: 완료 | 부분 | 없음 (탭 이름)
processed: YYYY-MM-DD
tags: [주간회의]
---
# 주간회의 YYYY-MM-DD
## 요약            ← 3~5줄
## 내 업무 (발표자료 기준)   ← 프로젝트별 진행내용/결과 · 금주계획 · 지난주 대비 변화
## 내 업무 관련 회의 메모
## 원장·교수 피드백 및 조직 논의
## 연구원별 동향      ← ### [[이름]] 별로, 메모에 적힌 것만
## 내 업무와의 연결점 [추정]
## 확인 필요
## 출처
```

## 기록 규칙
- **사실과 계획을 나눈다.** '예정', '계획', '완료', '진행 중'을 원문대로 쓴다. 슬라이드의 금주계획을 실적으로 쓰지 않는다.
- 지난주에 있던 항목이 이번 주에 없어도 완료·중단으로 판단하지 않는다. "이번 주 기재 없음"으로 쓴다.
- 보고일, 실제 수행 기간, 예정일을 구분한다. 슬라이드 기간 표기가 서로 맞지 않으면 `[확인 필요]`로 적는다.
- 메모가 짧아도 적힌 범위를 넘어 추측하지 않는다. AI 해석은 `[추정]`, 모호한 원문은 `[원문상 불명확]`으로 표시한다.
- 근거 표기는 [README](../README.md)의 Evidence conventions를 따른다.
- **제외:** 건강·사생활 정보(병가·반차 사유, 연차·휴가 일정, 개인 일정 사유), 개인별 인사평가 내용, 비밀번호·인증정보. 평가 제도·일정 같은 조직 차원의 절차는 기록할 수 있다.
- 회의 요일이 평소(화요일)와 다르면 요일을 적고, 이유가 메모에 없으면 `[추정]`으로만 쓴다. 동료 기록은 업무 맥락 파악용이며 평가에 쓰지 않는다.
- 금액은 원문 단위를 그대로 쓰고, 단위가 없으면 `[단위 미기재]`로 표시한다. (주간업무보고 슬라이드의 예산 비공개 규칙은 슬라이드 작성에만 적용한다.)
- 원본 슬라이드·문서는 수정하지 않는다. 공유 권한도 바꾸지 않는다.
